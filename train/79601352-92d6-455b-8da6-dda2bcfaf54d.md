Title: Unexpected `None` Return from `sorted` with Custom Key

Environment:

*   Language: Python 3.11.5
*   Operating System: macOS 13.6.3
*   Editor: Visual Studio Code v1.84.2

```python
data = [
    {"name": "Alice", "score": 95},
    {"name": "Bob", "score": 80},
    {"name": "Charlie", "score": 95},
    {"name": "David", "score": 70},
]

def get_name(item):
    return item["name"]

sorted_data = sorted(data, key=get_name)

print(sorted_data)
```

Observed Behavior:

The code produces a `TypeError`: `TypeError: '<' not supported between instances of 'str' and 'None'`. This occurs during the comparison within the `sorted` function. The traceback indicates the comparison is attempting to compare a string (the name) with `None`.

Expected Behavior:

The code should sort the list of dictionaries `data` alphabetically by the "name" key and print the sorted list to standard output. The `sorted` function should handle the comparison of strings without error.



Troubleshooting Steps:

1.  Verified that the `get_name` function returns a string.
2.  Inspected the `data` list for missing or `None` values.
3.  Tried using `lambda x: x["name"]` as the key.
4.  Checked for potential type inconsistencies within the dictionaries.
5.  Simplified the `data` list to a smaller, more predictable set.
