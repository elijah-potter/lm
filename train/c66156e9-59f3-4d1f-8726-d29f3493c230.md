Title: Unexpected Type Conversion in Python List Comprehension

```python
# Python 3.11.5
# macOS 13.6.3
# Visual Studio Code

numbers = [1, 2, 3, 1, 1, 3]

# The following list comprehension is intended to
# produce a list of integers representing the unique
# elements of 'numbers', preserving the original order.

unique_numbers = []
[unique_numbers.append(x) for x in numbers if x not in unique_numbers]

print(unique_numbers)
```

Observed Behavior:

The `unique_numbers` list contains the integers `[1, 2, 3, 1, 1, 3]`.
The list comprehension appears to append all elements of
the original `numbers` list, rather than only the unique ones.

Expected Behavior:

The `unique_numbers` list should contain only the unique
elements of the `numbers` list, in the order they appear
originally.  The expected output is `[1, 2, 3]`.

Troubleshooting Steps:

1. Verified that the `not in` operator functions as expected
   with simple list checks.
2. Examined the `append` method's behavior.
3. Attempted to use a `set` to determine unique elements,
   but order is not preserved.
4. Simplified the list comprehension to isolate the issue.
5. Checked for unintended side effects within the list
   comprehension's scope.
