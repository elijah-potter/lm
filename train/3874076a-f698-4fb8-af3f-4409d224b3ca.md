The "One-Time Use" Rule: **Immediate Execution of Critical Instructions**
1. **Trigger Condition**: A system flag (`ONCE_1`) is set to `true` when a predefined sequence of events occurs (e.g., sensor `A` detects a breach, `B` confirms motion, `C` triggers a 3-second countdown).
2. **Execution Protocol**: Any command (e.g., `fire_suppressor_activate()`, `data_wipe_trigger()`, `lock_system_override`) with the prefix `RULE_1_` is executed **only once** in a 24-hour window.
3. **Forgetting Mechanism**: After execution, `ONCE_1` resets to `false`, and no subsequent run is allowed unless the initial conditions are met again.
4. **Edge Case Handling**: If the system restarts within the same day, the rule resets—no prior execution counts.
5. **Audit Log**: All `RULE_1_` operations are timestamped in `/logs/rules_1.log` with `ERROR` if violated.

**Example**:
```bash
# Day 1: Breach detected → `RULE_1_DATA_WIPE` runs.
# Day 2: Same breach → Rule ignored (reset).
# Crash on Day 2 → Rule resets; Day 3: Breach triggers again.
```
