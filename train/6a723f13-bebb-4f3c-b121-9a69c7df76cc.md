Title: Unexpected Type Conversion in Python List Comprehension

Environment:
Python 3.9.13
macOS 12.6
Visual Studio Code

```python
data = [1, 2, 3, 1.5, 2.7]

result = [str(x * 10) for x in data]

print(result)
```

Observed Behavior:

The list comprehension produces a list of strings,
as expected. However, the floating-point numbers (1.5 and 
2.7) are converted to strings with an unnecessary level
of precision. The output is: `['10', '20', '30', '15.0', 
'27.0']`.

Expected Behavior:

The code should produce a list of strings where all numbers,
including floating-point numbers, are converted to strings
without extraneous decimal places. The expected output is:
`['10', '20', '30', '15', '27']`.

Troubleshooting Steps:

1. Verified that the input data type is a list of numbers.
2. Examined the `str()` function's behavior with floats.
3. Attempted to format the output using an f-string:
   `[f'{x * 10:.0f}' for x in data]`. This produced
   the desired output.
4. Searched for known issues related to implicit type
   conversions in list comprehensions.
5. Tested with different floating-point numbers to
   confirm consistency.
