1. **Functional vs. Procedural Programming**:
   - **Functional**: Treats computation as evaluation of mathematical functions, avoids mutable state, uses immutable data (e.g., pure functions, immutability).
   - **Procedural**: Focuses on procedures (functions) that operate on data, often mutable state, linear execution flow (e.g., loops, conditionals).

2. **JSON vs. XML**:
   - **JSON**: Key-value pairs, lightweight, easy to parse, no escaping, supports Unicode.
   - **XML**: Tags-based structure, verbose, supports attributes, DTD/Schema validation, XML namespaces.

3. **Thread vs. Process**:
   - **Thread**: Lightweight execution unit within a process, shares memory, faster context-switching but risk of race conditions.
   - **Process**: Independent execution unit with its own memory space, isolated, higher overhead but safer for concurrent operations.

4. **HTTP GET vs. POST**:
   - **GET**: Retrieves data (safe, cacheable), URL-encoded query params, no body sent.
   - **POST**: Sends data (unsafely), can use arbitrary data in body, often used for submissions (e.g., form submissions).

5. **Inheritance vs. Composition**:
   - **Inheritance**: "Is-a" relationship, child class inherits parent’s properties/methods (can lead to tight coupling).
   - **Composition**: "Has-a" relationship, class contains objects of other types (more flexible, avoids inheritance pitfalls).

6. **Static vs. Dynamic Typing**:
   - **Static**: Types checked at compile-time (e.g., Java, C++), type safety, but less flexibility in runtime.
   - **Dynamic**: Types checked at runtime (e.g., Python, JavaScript), flexible but risks type errors.

7. **SQL vs. NoSQL**:
   - **SQL**: Structured relational data, ACID compliance, joins, schema-defined (e.g., MySQL, PostgreSQL).
   - **NoSQL**: Schema-less, unstructured data, horizontal scaling, supports varied data types (e.g., MongoDB, Cassandra).

8. **Asynchronous vs. Synchronous Programming**:
   - **Synchronous**: Blocks execution until operation completes (sequential, simple but inefficient for I/O).
   - **Asynchronous**: Non-blocking, uses callbacks/promises to handle concurrent operations (better for I/O-heavy tasks).

9. **REST vs. GraphQL**:
   - **REST**: stateless, uses HTTP methods (GET, POST), single endpoint per resource, strict schema via APIs.
   - **GraphQL**: flexible query language, single endpoint, resolves nested data in one request, supports subscriptions.

10. **Frontend vs. Backend**:
    - **Frontend**: Handles UI/UX, client-side rendering, state management (e.g., React, Vue).
    - **Backend**: Manages logic, APIs, databases, server-side processing (e.g., Node.js, Django).
