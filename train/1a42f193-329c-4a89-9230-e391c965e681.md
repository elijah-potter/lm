1. **Binary vs. Hexadecimal**:
   - Binary uses only digits **0** and **1** to represent data.
   - Hexadecimal uses **16 digits (0–F)** for compact representation, where each hex digit = **4 binary digits (nibble)**.

2. **JSON vs. XML**:
   - JSON: Key-value pairs, lightweight, uses **double quotes** (`"key": "value"`), no comments.
   - XML: Tag-based structure (`<tag>value</tag>`), supports attributes and comments, more verbose.

3. **Linux `grep` vs. `awk`**:
   - `grep`: Simple text search (case-sensitive by default).
   - `awk`: Full-fledged pattern-processing (supports variables, arithmetic, file parsing).

4. **`find` vs. `locate`**:
   - `find`: Searches filesystem (slow, real-time).
   - `locate`: Uses pre-built database (fast, requires `updatedb`).

5. **`sed` vs. `awk`**:
   - `sed`: Stream editor (streamline text with substitutions/replacements).
   - `awk`: Pattern-scanning (supports complex logic, fields, variables).

6. **`diff` vs. `comm`**:
   - `diff`: Compares two files line-by-line, highlights changes.
   - `comm`: Lists common/unique lines from two sorted files (requires sorted inputs).

7. **`ls -l` vs. `ls -lR`**:
   - `ls -l`: Lists files in long format (permissions, owner, size).
   - `ls -lR`: Recursively lists directories (shows contents inside).

8. **`man` vs. `info`**:
   - `man`: Manual pages (concise, often formatted).
   - `info`: User-oriented documentation (interactive, tree-like navigation).

9. **`cut` vs. `awk` for column extraction**:
   - `cut`: Simple column extraction (e.g., `-f 2` for 2nd field).
   - `awk`: More flexible (e.g., `awk -F, '{print $2}'`).

10. **`tar` vs. `zip`**:
    - `tar`: Archiving (supports `.tar`, `.tgz`, `.xz`; layering files).
    - `zip`: Compression (supports `.zip`; cross-platform, encryption).
