The team misunderstood the API documentation regarding the **timeouts** for the `/fetch-data` endpoint. Initially, they assumed the 30-second default timeout was per request, but it was actually cumulative for the entire session. After debugging, they adjusted their code to split requests into smaller batches (5s timeout each) and observed that the system began processing data efficiently without throttling.

The error log showed repeated `Connection Timeout` errors, which clarified the root cause. Now, the team uses a custom retry mechanism with exponential backoff to handle transient failures, ensuring consistent performance.
