Title: Unexpected Behavior with `std::move` and `std::vector`

Environment:
* Language: C++
* Compiler: GCC 11.3.0
* OS: Ubuntu 20.04
* Editor: Visual Studio Code

```cpp
#include <iostream>
#include <vector>
#include <utility>

int main() {
  std::vector<int> a = {1, 2, 3};
  std::vector<int> b;
  b = std::move(a);

  std::cout << "Size of a: " << a.size() << std::endl;
  std::cout << "Size of b: " << b.size() << std::endl;

  return 0;
}
```

Observed Behavior:
The program outputs "Size of a: 0" and "Size of b: 3". This
indicates that `a` is empty after the `std::move` operation, which
is expected. However, the program then continues to execute
without issue, implying that `a` is still a valid `std::vector`.

Expected Behavior:
It is anticipated that after the `std::move` operation, `a` will be
in a valid, albeit potentially empty, state, but that accessing
its members (e.g., `a.size()`) might produce undefined behavior
or a crash due to the internal state being potentially invalid.
The program’s continued execution without error is surprising.

Troubleshooting Steps:

1. Verified compiler flags do not interfere with `std::move`.
2. Checked for memory leaks using Valgrind; no issues found.
3. Examined the `std::vector` implementation for potential bugs.
4. Tested with different data types within the `std::vector`.
5. Searched online forums and documentation for similar reports.
