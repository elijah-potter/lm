Comparison:
1. **Binary Search Tree (BST)** vs **Hash Table**
   - **BST** organizes data in a node-based, tree structure with O(log n) average search time but O(n) worst-case (unbalanced).
   - **Hash Table** uses hashing for O(1) average-time operations but requires extra memory for collision resolution (e.g., chaining or open addressing).

2. **Concurrent Hashing (Java `ConcurrentHashMap`)** vs **Thread-Local Storage**
   - **Concurrent Hashing** distributes load across segments, allowing parallel reads/writes with fine-grained locks (e.g., `ConcurrentHashMap`).
   - **Thread-Local Storage** assigns per-thread data isolation (e.g., `ThreadLocal`), reducing contention but increasing memory overhead.

---
**Key Metric:** Trade-off between speed (BST: structured, HT: hash) and scalability (BST: balanced vs HT: parallelism).
