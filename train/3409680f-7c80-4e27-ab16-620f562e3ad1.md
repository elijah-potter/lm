Title: Unexpected Type Conversion in Python List Comprehension

```python
# Python 3.11.5
# macOS 13.6.3
# Visual Studio Code

numbers = [1, 2, 3, 1, 2, 3]
result = [str(x*2) for x in numbers]
print(result)

numbers2 = [1, 2, 3, 1, 2, 3]
result2 = [x*2 for x in numbers2]
print(result2)
```

Observed Behavior:

The first list comprehension converts each integer to a string
before multiplication, yielding `['2', '4', '6', '2', '4', '6']`.
The second list comprehension performs multiplication before
returning the integer values, resulting in `[2, 4, 6, 2, 4, 6]`.

Expected Behavior:

Both list comprehensions should produce identical results.
The intention is to multiply each element by two and return
the resulting integer. The type conversion to string should
only occur when explicitly requested.

Troubleshooting Steps:

1. Verified Python version using `python --version`.
2. Inspected the list comprehension syntax for errors.
3. Checked for implicit type coercion within the loop.
4. Tested the expression `str(x*2)` outside the list comprehension.
5. Simplified the list comprehension to `[x for x in numbers]`.
